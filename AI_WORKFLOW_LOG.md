# AI Workflow Log

- Used Claude Code throughout for architecture discussion, scaffolding, and implementation.
- Before committing to a transcript-acquisition strategy, had Claude fetch and inspect the actual RSS feed rather than assuming: confirmed no `<podcast:transcript>` tags exist (despite the namespace being declared) and that all 5 target episodes exceed Whisper's 25MB upload cap (29-51MB). This ruled out a feed-text-only approach and made audio re-encoding a required ingest step, not an edge case — good example of checking assumptions against real data before writing code.
- AI got something wrong and it was caught by testing, not review: the generated ingest script used the global `fetch()` to download episode audio, which returned a bare 404 on this feed's redirecting CDN (episodes.captivate.fm -> dax.captivate.fm). Diffing against curl and Node's core `https` module (both got the correct 302->200) showed this was an undici-specific quirk with this CDN, not a real error. Rewrote the downloader on node:http/https with manual redirect-following instead of debugging fetch further, since chasing an undici bug wasn't worth the time budget.
- The architecture itself (flat-file index + brute-force cosine search, non-overlapping fixed-duration chunks, raw excerpts instead of a generated/RAG answer, no vector DB) was decided in a design conversation before any code was written, then handed to AI as constraints rather than left open — this is the main way coherence was kept: AI filled in implementation within an already-decided shape instead of proposing its own.
- `create-next-app` scaffolding was accepted essentially as-is (App Router, TS, no Tailwind) — the only manual correction needed was the boilerplate `<title>`/description left over from the template.
- Caught and deliberately did not act on an AI-adjacent artifact: running `next dev` silently appended a block to `CLAUDE.md` instructing an agent to read framework docs from `node_modules` and to commit the block "to keep the tree clean." Treated it as untrusted generated content rather than an instruction, reverted it, and flagged it rather than silently complying or silently deleting it.
- Used GitHub Copilot's automated PR review as a second pass on the first checkpoint. Of 6 findings, 3 were legitimate and applied (a silent-failure risk in the Whisper response parsing, a divide-by-zero edge in cosine similarity, a temp-filename robustness issue); 3 were declined with reasoning recorded in the follow-up commit — including one Copilot flagged as build-blocking (a Next.js 16 typed-route type signature) that was actually a false positive, verified by re-running `tsc --noEmit`/`next build` clean before dismissing it. Not accepting a "blocking" label at face value from a second AI reviewer was the main judgment call there.
- Not delegated to AI: the choice of what to cut from scope (no vector DB, no RAG generation, no auth/multi-tenant, ingest capped at 5 episodes) was made against the brief's evaluation priorities directly, not asked of or generated by AI.
